# 访谈记录稿

> 以下对话基于本次访谈整理，已取得同意并完成去标识化，原话按记录归档。

## R01｜软件学院硕士研究生

- 角色：北京航空航天大学软件学院硕士研究生，研二，软件工程方向
- 方式：文字访谈
- 日期：2026-10-11
- 主题：论文检索、数据集版本、成果维护

**访谈者：** 你最近一次集中查找论文或数据集时，主要遇到什么问题？

**受访者：** 论文一般从学术搜索、课题组群文件和老师推荐的链接里找。真正麻烦的是找到之后，过一段时间很难记住是哪一个版本，数据集从哪里下载、什么时候下载的也容易忘。

**访谈者：** 你现在如何保存这些信息？

**受访者：** 文献放在 Zotero，实验参数写在 Markdown，数据集说明有时单独放在项目目录。三个地方没有关联，换电脑或和同门协作时就要重新解释。

**访谈者：** 如果平台提供学术成果和数据来源管理，你最希望看到哪些字段？

**受访者：** 至少要有来源链接、版本号、更新时间、作者和机构。数据集还要能写下载日期、划分方式和随机种子。成果信息如果过期，最好能直接发起纠错。

**需求转化：** 建立 `Achievement`、`DataSource`、`DatasetVersion` 和 `ProcessingLog` 关联；检索结果显示来源和更新时间；支持版本记录、纠错申请和处理状态。

## R02｜软件学院博士研究生

- 角色：北京航空航天大学软件学院博士研究生，博三，人工智能方向
- 方式：文字访谈
- 日期：2026-10-11
- 主题：阶段成果、导师反馈、成果归属和公开范围

**访谈者：** 博士阶段最需要一个成果平台帮你解决什么问题？

**受访者：** 我需要一个清晰的阶段视图，能看到论文、项目、专利分别处于什么状态，哪些材料还要补。现在信息散落在邮箱、表格和课题组系统里，到了中期或毕业节点容易漏掉。

**访谈者：** 如果发现论文或项目错误地归到了别人名下，你会怎么处理？

**受访者：** 先找来源，再联系管理员或秘书修改。最担心的是改完之后没有记录，也不知道谁审核过。认领流程可以有材料验证，但不要让科研人员反复填很复杂的表格。

**访谈者：** 哪些信息你希望公开，哪些信息需要自己控制？

**受访者：** 论文、项目和研究方向可以公开；手机号、邮箱、未公开的在研成果和内部评价不应公开。最好每个字段都有公开开关，认领成功后由本人维护。

**需求转化：** 提供学者门户、成果阶段状态、认领申请、材料验证、审核记录、纠错申诉和字段级公开控制；通过通知反馈审核进展。

## R03｜科研人员与课题组协作角色

- 角色：高校科研人员，承担课题组成果整理和项目协作
- 方式：文字访谈
- 日期：2026-10-11
- 主题：多人协作、数据治理和更新机制

**访谈者：** 课题组通常由谁维护成果清单？

**受访者：** 论文和项目由不同的人维护，年终或申报时再集中汇总。不同成员使用的机构名称、作者写法和成果类型不一致，重复记录很常见。

**访谈者：** 你认为管理员后台最需要什么能力？

**受访者：** 能看到采集任务是否成功、哪些记录被判定为重复、哪些作者需要人工确认。每次修改最好都有前后值和原因，后面追查时不用靠记忆。

**访谈者：** 对自动分类或自动消歧有什么要求？

**受访者：** 可以给候选结果，但不能直接覆盖正式数据。低置信度记录要进入人工队列，管理员能接受或驳回，并且保留来源。

**需求转化：** 建立采集任务、ETL处理日志、作者/机构消歧候选、人工审核队列和审计日志；自动规则输出置信度，管理员可以复核和回滚。

## 归纳结果

三份访谈共同指向四个需求：

1. 成果、文献、数据集和实验记录需要建立可追溯关联。
2. 认领和纠错需要低负担入口、审核状态和处理记录。
3. 公开字段、来源、版本和更新时间需要由系统明确管理。
4. 自动分类与消歧只能提供候选，最终结果保留人工复核和审计。
