## 1. 规范目的与范围

本规范将 SRS 中的数据采集、清洗治理、去重消歧、检索排序、统计聚合和任务控制需求转化为可编码、可测试的模块契约。规范适用于一期 P0 数据链路，并为合作关系网络/领域热点分析 P1 功能提供统一输入。

本规范覆盖：

- 外部记录进入系统后的标准化、校验、质量标记和幂等导入。
- 成果、作者和机构的候选匹配、去重合并和人工复核。
- 搜索字段、过滤、排序、分页、来源展示和索引更新。
- 采集任务状态、重试、停止、错误记录和审计。
- 统计聚合的口径、空数据处理和 P1 分析输出。

本规范不覆盖：收费数据库抓取、全文内容下载、自动认领通过、无人审核的高置信度消歧、数据库物理建表和最终 REST/OpenAPI 文件。

本文中的权重、阈值、分页上限、重试间隔和告警阈值是本次建模提出的默认配置，不是问卷或访谈测得的事实，也不是已验证的准确率承诺。发布为开发基线前应由团队评审确认；以后调整必须记录配置版本、理由和受影响的验收场景。

## 2. 术语、输入与输出

| 术语 | 说明 |
|---|---|
| 原始记录 | 从公开 API、开放数据或人工导入获得、尚未标准化的 JSON/CSV 记录 |
| 规范记录 | 经过字段映射、类型校验和标准化后的内部记录 |
| 候选匹配 | 算法认为可能属于同一成果/作者/机构、等待管理员确认的关系 |
| 确定匹配 | 管理员确认并留下证据和审计记录的实体关系 |
| 低置信度 | 匹配分或证据不足，需要人工复核的结果；分数不是概率 |
| 处理批次 | 一个采集任务产生的可追踪输入、输出、错误和统计集合 |

### 2.1 统一记录元数据

所有成果、作者和机构记录必须携带：

| 字段 | 类型 | 约束 |
|---|---|---|
| `source_name` | string | 必填；来自登记的数据源名称 |
| `source_url` | string | 必填；来源记录或 API 文档地址 |
| `source_record_id` | string | 推荐；来源侧稳定标识符 |
| `collected_at` | datetime | 必填；UTC ISO-8601 |
| `license_note` | string | 必填；许可或条款核验摘要 |
| `review_status` | enum | `pending`、`reviewed`、`rejected` |
| `visibility` | enum | `public`、`private`；未公开来源及敏感信息默认为 `private` |
| `quality_flags` | array | 质量问题代码集合，不覆盖原始值 |
| `batch_id` | string | 必填；关联采集任务批次 |

原始字段只读保存，标准化字段另存。任何清洗、合并、人工修改都必须写入审计日志，包含对象 ID、动作、操作者、时间、前值、后值和原因。

新输入的规范记录默认 `pending`。管理员可逐条审核或批量批准来源已核验、无冲突的规范记录，批量决定必须保留对象清单和版本。算法候选和字段级个人隐私不得因批量批准而跳过独立审核；拒绝记录保存为 `rejected`，不进入公开检索。只有审核通过且公开的字段参与访客检索、分页计数和聚合。

## 3. 模块与接口契约

| 模块 | 输入 | 输出 | 失败处理 |
|---|---|---|---|
| Collector | 数据源配置、范围、游标 | 原始记录流、游标、批次统计 | 记录 HTTP/限频/解析错误；按策略重试 |
| Normalizer | 原始记录 | 规范记录、质量标记 | 单条失败进入 dead-letter 集合，不阻断同批有效记录 |
| Matcher | 规范成果/作者/机构 | 候选、分数、决策、解释 | 低置信度进入人工队列 |
| Indexer | 已审核规范记录 | 索引文档、索引版本 | 写入失败保留待同步状态并可重放 |
| SearchService | 查询词、过滤器、分页、排序 | 结果、聚合、来源和更新时间 | 参数错误返回字段级错误；超时返回请求编号 |
| Aggregator | 时间范围、维度、过滤器 | 统计结果、口径、样本量、更新时间 | 空数据返回空集和原因，不生成零值结论 |
| AuditService | 对象、动作、前后值、原因 | 审计日志 ID | 审计失败视为任务失败，不静默忽略 |

### 3.1 通用接口约定

- 所有接口携带 `request_id` 和 `schema_version`；数据处理接口另外携带 `task_id`、`batch_id`，交互式搜索不伪造批次 ID。
- 来源记录幂等键为 `source_name + source_record_id`，跨批次不产生新实体；同一内容重放为 no-op，有真实变化才产生新版本。缺少来源 ID 时使用规范后的原始载荷 SHA-256 作为输入重放键；不能据此判断不同载荷是同一成果。
- 管道摘要包含 `status`、`processed_count`、`warning_count`、`error_count`；各模块使用自己的输出类型；失败响应包含 `code`、`message`、`request_id`。
- 时间统一使用 UTC 存储和 ISO-8601 传输；前端按用户时区展示。
- 结构化错误码至少包括：`INVALID_INPUT`、`SOURCE_RATE_LIMITED`、`SOURCE_UNAVAILABLE`、`SOURCE_NOT_APPROVED`、`SCHEMA_INVALID`、`INDEX_SYNC_FAILED`、`AUDIT_WRITE_FAILED`、`SERVICE_UNAVAILABLE`、`CONFLICT`、`FORBIDDEN`；`LOW_CONFIDENCE` 是候选质量标记，不将待复核记录计入技术失败。

### 3.2 最小内部数据类型

- `NormalizedRecord`：`record_id`、`type`、`title`、可空 `year`、`identifiers[]`、`authors[]`、`institutions[]`、`domains[]`、上述来源元数据、`record_version`。
- `ProcessingResult`：`status=accepted/rejected/duplicate`、可空 `normalized_record`、`warnings[]`、`errors[]`、`raw_record_ref`、`rule_version`。
- `MatchCandidate`：`candidate_id`、左右对象 ID、`entity_type`、`feature_scores`、`score`、`evidence_level`、`decision=pending/accepted/rejected`、`algorithm_version`、证据引用。
- `SearchRequest`：`q`、`entity_type=achievement/scholar/institution`（默认 `achievement`）、`filters`、`page`（默认 1）、`page_size`（默认 20）、可空 `snapshot_token`。
- `SearchResponse`：`request_id`、`items[]`、`total`、`page`、`page_size`、`has_next`、`facets`、`snapshot_token`、`index_version`、`updated_at`。
- `TaskSummary`：`task_id`、六态 `state`、`retry_count`、计数摘要、可空 `last_error`、持久化游标、创建/开始/结束时间和配置版本。

字段类型与行为是开发契约；REST 路径、数据库表型和具体消息队列技术在后续接口/构件设计中确定。

## 4. 数据清洗规范（MOD-01）

### 4.1 处理顺序

对每条原始记录按以下顺序处理，步骤编号写入 `processing_log`：

1. 解析 JSON/CSV，并检查编码、必填字段和来源元数据。
2. 映射来源字段到统一字段，保留原始字段快照。
3. 显示字段采用 Unicode NFC、去首尾空白；比较字段单独采用 NFKC、空白压缩和 casefold。保留重音，不把不同姓名或技术名词强行等同。
4. 标准化 DOI、URL、作者姓名、机构名称、日期和成果类型。
5. 校验字段长度、枚举值、日期范围和标识符格式。
6. 生成 `quality_flags`，不因非关键字段缺失丢弃整条记录。
7. 进入成果/作者/机构匹配和索引准备队列。

### 4.2 字段规则

| 字段 | 规则 | 失败结果 |
|---|---|---|
| 标题 | 去首尾空白；保留原文；比较副本保留技术符号；长度 1～500，不静默截断 | 缺失或超长记录级拒绝，保留原始值 |
| DOI | 去首尾空白；去前缀 `doi:`、`http(s)://doi.org/` 或 `http(s)://dx.doi.org/`；casefold；正则校验 `^10\.[0-9]{4,9}/\S+$` | 缺失允许；格式错误设规范 DOI 为 null，标记 `INVALID_DOI`，保留原值 |
| URL | HTTP/HTTPS 且具备主机名；保留 query 和原始 URL，比较副本可去片段 | 来源 URL 不合法则拒绝；辅助 URL 不合法则标记 `INVALID_URL` |
| 作者姓名 | 保留显示名、顺序、重音、连字符；比较副本统一空白和大小写 | 缺失标记 `MISSING_AUTHOR`，不推断匿名作者身份 |
| 机构名称 | 应用机构别名表；保留原名和规范名 | 未命中别名标记 `UNMAPPED_INSTITUTION` |
| 年份 | 四位数字，范围 1800～采集时 UTC 年份+1 | 缺失/越界置 null，并标记 `MISSING_YEAR`/`INVALID_YEAR` |
| 成果类型 | 仅允许 `paper`、`patent`、`project`、`award` | 未知值进入人工复核 |
| 领域 | 一级领域 + 零个或多个二级标签；保存来源和置信度 | 冲突标记 `DOMAIN_CONFLICT` |

### 4.3 质量决策

- 缺少标题、来源或批次 ID：记录级拒绝，错误码 `SCHEMA_INVALID`。
- 未知成果类型：保留在暂存复核区；未纠正前禁止进入正式成果集合及公开统计。
- DOI、年份、机构等非关键字段异常：记录保留，写入质量标记；无效值不参与候选计算。
- 原始记录重复出现：不重复入库，批次统计增加 `duplicate_input_count`。
- 任何清洗规则不得静默覆盖原始值；规范值变化必须可由日志重建。

### 4.4 验收标准

- 同一 DOI 的大小写、前缀和 URL 写法生成相同规范 DOI。
- 同一来源记录重放两次只产生一条正式记录。
- 缺失非关键字段的记录可入库但带质量标记；缺失标题或来源的记录可定位到错误集合。
- 每条正式记录可反查原始记录、处理批次、处理步骤和错误/警告。

## 5. 去重与消歧规范（MOD-02）

### 5.1 成果去重优先级

先按来源记录幂等键排除重复输入，再按以下顺序产生实体去重候选；相同来源记录重放不属于跨实体合并：

1. 相同有效规范 DOI：生成同一论文的强标识符候选。
2. 同一数据源的稳定实体 ID：生成强标识符候选，不跨来源比较裸 ID。
3. 专利的国家/地区+申请号+文献种类码、项目的资助机构+批准号、获奖的颁奖机构+年度+编号相同：生成强标识符候选。奖项没有编号时使用名称、年度、等级和获奖者计算候选，禁止仅凭奖项名合并。
4. 无稳定标识符时计算复合匹配分，进入候选匹配流程。

标识符键采用 `{type}:{namespace}:{normalized_identifier}`；不同类型或命名空间不碰撞。同类型中存在不同有效 DOI/ORCID 等互斥标识符时，不允许高相似度覆盖冲突，转交管理员核实。强标识符候选和高分候选均需人工确认后才能合并正式实体，遵守 SRS NFR-02。

候选召回只在同成果类型内运行：优先查有效标识符；无标识符时按比较标题的字符二元组倒排召回，再以年份差不超过 1（缺失年份不过滤）筛选。标题相似度取前 50 个候选，ID 升序破同分。作者候选按规范名召回，机构候选按审核过的别名表及国家/地区召回。复核不确定时保留独立记录。

### 5.2 无标识符成果匹配分

对规范后的候选记录计算：

`score = 0.45 * title_sim + 0.20 * year_sim + 0.20 * author_sim + 0.10 * venue_or_org_sim + 0.05 * source_agreement`

其中：

- `title_sim`：规范标题字符二元组 Jaccard 与 `1 - Levenshtein(a,b)/max(len(a),len(b))` 的平均值，适用于中英文；单字符按单字符集合处理，`C++`、`C#` 的符号保留。
- `year_sim`：同年为 1，相差 1 年为 0.5，相差超过 1 年为 0。
- `author_sim`：作者规范名集合的 Jaccard 值。
- `venue_or_org_sim`：审核后的期刊/会议或机构 ID 相同为 1，否则使用规范文本的归一化编辑相似度。
- `source_agreement`：来源名称不同且标题、年份、作者集合均一致时为 1，否则为 0；它只作启发式证据，不表示来源确实独立。

任一特征缺失时该项为 0，不对剩余权重重新归一化；两个空集合不计为相同。所有分数范围为 [0,1]，阈值判断使用未舍入分数，界面显示四位小数。

决策阈值：

| 分数 | 决策 | 处理 |
|---|---|---|
| `score >= 0.90` 且无冲突标识符 | 高置信度候选 | 推荐合并，管理员确认后合并，保留来源集合 |
| `0.75 <= score < 0.90` | 待人工复核 | 生成候选关系、分数和特征解释 |
| `score < 0.75` | 保持独立 | 不合并；可在后续批次重新计算 |

### 5.3 作者消歧

作者候选分数为：

`author_score = 0.35 * name_sim + 0.25 * institution_sim + 0.20 * orcid_match + 0.10 * coauthor_overlap + 0.10 * topic_overlap`

- ORCID 格式和校验位均有效时参与比较；一致为强证据候选，冲突禁止合并并转人工核实。ORCID 公开记录不能自动通过门户认领。
- `author_score >= 0.92` 且无冲突标识符：高置信度候选，仍须人工确认。
- `0.70 <= author_score < 0.92`：人工复核。
- 低于 0.70：保持独立。
- 同名不同机构不得仅凭姓名合并；机构别名须先经过机构规范化。

`name_sim` 使用归一化编辑相似度；`institution_sim` 使用审核机构 ID 集合 Jaccard；`orcid_match` 为双方有效 ORCID 相同的 0/1 指示；共同作者和主题使用已审核 ID 集合 Jaccard。缺失特征为 0，冲突规则优先于加权分数。同名不同机构可以是作者迁移等情形，系统保持候选而不武断判定不同人。

### 5.4 机构消歧

优先使用来源稳定 ID，其次使用机构规范名和国家/地区上下文。已审核别名表可生成规范字段；未审核映射、名称相似或层级/地区冲突进入人工队列。机构合并不得删除原名，必须保留别名和来源；院系与学校用上下级关系表示，不合并成同一机构。

### 5.5 合并与回滚

- 合并产生 `merge_event_id`，记录主记录、从记录、字段来源和算法版本。
- 同源新版本只生成更新候选；跨来源字段按登记的字段级优先级推荐。人工已确认字段优先保留；机构归属优先机构官方页，论文书目优先原出版登记，专利状态优先主管机关。优先级只产生建议，冲突值和来源全部保存，由管理员决定。
- 人工驳回候选后，将候选标记为 `rejected`，在同一算法版本和输入不变时不重复提示。
- 任何合并可由管理员回滚；回滚恢复合并前快照并写入审计日志。

### 5.6 验收标准

- 同一来源重放不产生重复记录；跨来源强标识符匹配在人工确认后只保留一个公开成果 ID。
- 作者 ORCID 冲突不会自动合并。
- 达到候选阈值的成果及作者进入人工队列，高分也不自动覆盖正式实体；展示分数、缺失字段、冲突、特征和来源。
- 合并、驳回和回滚均可追踪，原始记录不丢失。

## 6. 检索与排序规范（MOD-03）

### 6.1 索引字段

索引文档至少包含：`achievement_id`、`type`、`title`、`title_normalized`、`authors`、`institutions`、`domains`、`year`、`identifiers`、`source_name`、`source_url`、`collected_at`、`updated_at`、`review_status`、`quality_flags`、`visibility`。

只将 `review_status=reviewed` 且 `visibility=public` 的允许字段放入访客公开索引。待复核和隐藏记录不参与公开总数、分面统计、自动补全或关系网络；管理员查询它们时仍须校验治理权限。学者、机构对象使用独立文档类型，保留其允许公开的 ID、名称、领域、已审核关联成果和来源，分页总数按当前 `entity_type` 计。

### 6.2 查询处理

1. 校验分页参数：`page >= 1`，`1 <= page_size <= 100`；非法参数返回 `INVALID_INPUT`。
2. 对关键词做 Unicode NFC、空白压缩和大小写无关处理；空关键词允许仅按过滤器查询。
3. 过滤器支持 `type`、`year_from`、`year_to`、`domain_id`、`institution_id`、`author_id`，多个过滤器采用 AND，同一字段多值采用 OR。
4. 校验成果类型白名单、年份范围和 `year_from <= year_to`；不认识的字段拒绝，不能静默忽略。组合过滤无法满足时返回空集合。
5. 结果默认按“标识符精确命中优先、相关性降序、年份降序（null 最后）、比较标题/名称升序、对象 ID 升序”排序。
6. 返回结果必须包含来源、更新时间、成果类型和质量/审核状态摘要。

### 6.3 排序公式

`rank = 0.50 * text_score + 0.20 * identifier_score + 0.15 * entity_score + 0.10 * recency_score + 0.05 * quality_score`

- `text_score`：成果标题 3.0、作者 2.0、机构 1.5、领域 1.0 的字段加权 BM25 分数 b，经 `b/(1+b)` 归一化；空关键词时为 0。学者/机构的名称权重 3.0，领域 1.0，其余缺失项为 0。
- `identifier_score`：DOI、专利号、项目批准号精确匹配为 1，否则为 0。
- `entity_score`：至少提供作者/机构 ID 过滤器且命中为 1，未提供为 0；不做未定义的部分 ID 匹配。
- `recency_score`：有效年份使用 `max(0, 1 - 0.1 * max(0, current_year-year-1))`，缺失年份为 0，允许的下一年度成果为 1；学者/机构取允许公开的最新成果年份。
- `quality_score`：已审核且无关键质量标记为 1；有警告为 0.6；待复核为 0.2。

精确标识符匹配作为独立的第一排序键，不依赖加权公式保证优先。学者使用 ORCID、机构使用官方来源 ID 作为精确键。排序权重、索引版本和配置版本需记录；查询日志遵循最小化原则，不记录认证材料。

### 6.4 分页、聚合与异常

- 默认 `page_size=20`，最大 100；返回 `total`、`page`、`page_size`、`has_next`。
- 第一次查询建立 5 分钟有效的索引快照并返回 `snapshot_token`；继续翻页携带同一 token 和查询条件，在同一快照上读取。条件变化须建立新快照，过期或篡改返回 `CONFLICT` 并要求重启查询。仅靠稳定排序不能保证跨索引更新的分页一致性。
- 聚合支持成果类型、机构、领域和年度；聚合结果附 `sample_count`、时间范围、过滤条件和 `updated_at`。
- 无结果返回空数组和建议调整条件，不返回虚构推荐。
- 索引写入失败属于 `INDEX_SYNC_FAILED`；检索服务不可用返回 `SERVICE_UNAVAILABLE`。记录修改公开范围或撤销审核时，查询返回前按当前正式数据重新校验权限，立即排除旧快照中的已隐藏对象；此时允许页面少于 page_size，返回 `visibility_changed=true` 并重新计算公开总数/分面。公开范围不确定时关闭该页响应，禁止靠最终索引同步保护隐私。

### 6.5 验收标准

- 关键词 + 类型 + 年份 + 领域 + 机构组合过滤结果满足 AND/OR 规则。
- DOI 精确查询排在普通标题模糊匹配之前。
- 相同查询条件多次执行顺序稳定；分页不会重复或遗漏记录。
- 每条公开结果显示来源和更新时间；待复核记录不会混入访客公开结果。

## 7. 统计与 P1 分析规范（MOD-04）

### 7.1 基础统计

统计查询必须声明 `metric`、`dimensions`、`time_range`、过滤条件、快照/索引版本和数据更新时间。只统计已审核公开记录；成果数按合并后的 `achievement_id` 去重。同一成果同一作者或机构只计一次，多个机构各自可计 1，分组之和可能大于成果总数，界面必须注明。

领域统计默认使用主领域，辅助标签只有用户明确选择标签口径时才计入；缺失年份放入“未知年份”，年份过滤时排除。无数据返回 `sample_count=0` 和空序列，图表说明无数据；不能把缺失值伪造为已观测零值。已明确覆盖的年度无成果可以标 0，缺少年度覆盖证据的年份使用 null。

### 7.2 P1 分析二选一

实现阶段至少选择一个：

- **合作关系网络**：节点为人工已确认的学者 ID，边为公开论文中的共同署名关系；每篇论文中不同作者的无向两两组合各加 1，跨来源论文不得重复；禁止自环。同名未消歧记录不合并节点，边权为共同论文数。节点默认最多 100、边最小权重 1，过滤及截断须显示 `truncated` 和口径；同权重按作者 ID 排序。
- **领域热点时序**：按年度和领域统计去重成果数，至少提供近 5 年趋势；样本少于 5 条的领域标记为低样本，不进行排名结论。

输出必须包括数据范围、过滤条件、节点/趋势口径、样本量和更新时间；分析服务不得使用联系方式、内部评价或敏感情绪内容。

## 8. 采集任务、重试与幂等（MOD-05）

### 8.1 状态和转移

合法状态为：`待执行`、`运行中`、`成功`、`失败`、`重试`、`已停止`。只有管理员或调度器能触发状态转移；终态“成功”和“已停止”不可直接回到运行中，重跑必须创建新任务或明确生成新批次。

状态转移表与现有采集状态图一致：

| 原状态 | 事件/守卫 | 新状态 |
|---|---|---|
| 待执行 | 调度器获得唯一执行租约 | 运行中 |
| 运行中 | 数据与来源日志完成持久化、索引同步完成 | 成功 |
| 运行中 | 批次异常或关键审计失败 | 失败 |
| 失败 | 可重试且 retry_count < 3 | 重试 |
| 重试 | 等待结束且获得执行租约 | 运行中 |
| 待执行/运行中/失败/重试 | 管理员停止或重试额度耗尽 | 已停止 |

成功表示技术处理完成，不表示每条输入已审核或采集数据没有问题。摘要必须分别列出接收、拒绝、输入重放、待复核和索引同步数量。单条校验错误写入错误集合后继续批次；不能把来源结构整体变化误判成大量单条错误而继续。

### 8.2 重试策略

- 首次执行不计重试，`retry_count=0`；网络错误、HTTP 429/5xx、临时索引不可用：退避 `30s, 60s, 120s`，最多 3 次重试，总执行次数最多 4 次。429 有合法 Retry-After 时取其等待值与退避值的较大者；单一来源默认并发 1、最多每秒 1 请求，来源规定更严格时按更严格值。
- 认证失败、许可拒绝、字段结构不兼容：不自动重试，直接失败并要求管理员处理。
- 每次重试记录开始/结束时间、错误码、批次游标和重试次数。
- 达到上限仍失败时进入“已停止”，不得无限循环。

### 8.3 幂等与恢复

- 批次游标和 `source_record_id` 持久化；任务中断后从最近确认游标恢复。
- 入库采用唯一键或幂等键，重复消息只更新 `last_seen_at` 和批次统计。
- 索引写入失败时保留 `index_sync_pending`，可由重放任务补偿；补偿完成后写入审计日志。

- 正式记录变更与审计意图、索引同步意图必须同一持久化边界内提交，具体存储技术后续确定；消费者按对象 ID 和 record_version 幂等更新，旧版本事件不得覆盖新版本。重复同步失败不得在日志中谎报成功。
- 游标只有在该页每条记录已完成“接收/拒绝/重放”分类及日志持久化后推进。工作进程崩溃导致租约过期，调度器记失败并恢复，不允许同时有两个工作进程提交同一任务。
- 运行中停止先设置停止请求，在单页提交边界停止；已提交数据保留，不假称全部回滚；待执行/失败/重试可以立即停止。所有接口使用 expected_version 检查状态，重复请求返回同一结果，非法或竞态转移返回 CONFLICT。

### 8.4 提议的非功能验收基线

演示环境固定为不少于 4 核 CPU、8 GB RAM，加载至少 10,000 条去标识化公开或明确标注模拟来源的成果；预热后以 10 并发执行 200 次包含筛选的查询。建议验收目标：普通检索 P95 不高于 2 秒、基础统计 P95 不高于 3 秒、无丢失或重复正式 ID。记录环境、数据版本、查询集和实际测量结果；该目标尚未实测，不能在报告中写为已达成。

## 9. 门户认领与成果维护（MOD-06）

本模块是数据链路的身份授权边界，承接 UC-02、UC-03、UC-06、UC-07，不在此制定登录协议或外部认证供应商。

### 9.1 认领契约与状态

提交输入为申请人会话、scholar_id、材料引用、说明和幂等键；身份从会话读取，禁止客户端指定审核人或最终状态。以门户 ID 和申请人 ID 检查重复申请；同一门户存在未完成申请时返回 CONFLICT，门户已认领则引导 UC-09 申诉，不覆盖原管理者。

认领状态沿用 SRS 和现有图：“草稿→已提交→验证中→审核中→已通过/已驳回”；已提交可退回草稿；已提交/验证中/审核中可撤回为已撤回；已驳回补充后重新已提交。验证中只能做完整性与证据核对，最终授权必须管理员人工确认。审核动作包含 expected_version 和原因；通过后在同一持久化边界更新申请、门户 owner 和授权日志。两名管理员竞争审核时仅一个成功，另一方得到 CONFLICT。ORCID 相同不自动开通权限。

### 9.2 维护与隐私

成果管理须逐对象验证会话是否管理对应门户。学者只能编辑允许的展示副本和公开范围，不能覆盖来源快照、DOI、作者正式归属或管理员审核结果。争议修改以纠错申请处理；手机号、邮箱、未公开成果和内部评价默认不进公开索引。更新携带 expected_version，冲突拒绝并提示刷新；公开范围收紧立即影响检索与聚合，即便索引仍在补偿同步。

## 10. 纠错与通知（MOD-07）

纠错最小输入为目标 ID、问题类别、证据来源、描述和会话/访客提交凭据。访客可举报公开信息错误，不能修改实体；认领学者查看本人已认证申请，管理员处理。采用“已提交→处理中→已采纳/已驳回”，该状态只属于纠错记录，不增加本轮状态图。采纳后创建受审计的数据修订，驳回必须有原因；重复提交按幂等键处理。

审核、认领、纠错和任务状态事件先写入站内通知，再由通知服务分发；通知失败不撤销成功的业务决定。通知幂等键为事件 ID+接收者 ID+渠道，采用最多 3 次退避重试，耗尽保留失败状态供管理员重发。通知只包含申请编号与状态，验证材料不写入通知正文；日志保存每次尝试和结果。未登录访客只收到匿名回执编号，不向其暴露受保护处理细节。

## 11. 审计、可观测性和安全

- 每个任务、清洗批次、匹配决策、索引同步和人工审核生成可查询日志。
- 日志字段至少为 `request_id`、`batch_id`、`object_id`、`action`、`operator`、`created_at`、`before`、`after`、`reason`、`algorithm_version`。
- 日志不得记录密码、访问令牌、完整身份证件或非必要联系方式；验证材料采用受控存储引用。
- 指标至少包括任务成功率、记录处理量、错误率、重复率、低置信度率、索引延迟、查询耗时和通知失败数。
- 触发阈值：任务错误率 > 10%、索引延迟 > 15 分钟、连续 3 次任务失败时生成管理员告警。

### 12.1 可手工核对的样例

- 清洗输入 ` HTTPS://DOI.ORG/10.1000/ABC `，规范 DOI 为 `10.1000/abc`；另一次输入 `doi:10.1000/abc` 得到相同候选键。带内部空格的 `10.1000/a b` 无效，不自动删除空格把错误值“修好”。
- 无标识符成果：标题完全相同=1、同年=1、作者集合相同=1、上下文相同=1、不同来源但作者/年份均一致=1，score=1，仍是待人工确认的高置信度候选。作者字段缺失时 author_sim=0 且 source_agreement=0，score=0.75，不强行归一化为满分。
- 作者相似：同名=1、审核机构相同=1、ORCID 缺失=0、共同作者=0.5、领域相同=1，author_score=0.75，人工复核。双边 ORCID 有效但不同，冲突规则直接阻止合并，不由其余特征“拉高”通过。
- 检索：旧成果精确 DOI 命中，另一新成果标题模糊命中；前者第一排序键为 1，必先返回，不管二者 rank 如何。同一快照翻页稳定，隐藏后实时授权优先于快照。
- 合作网络：论文 A 有作者 S1、S2、S3；论文 B 有 S1、S2；A 的另一来源已合并。边 S1–S2 权重 2，S1–S3 与 S2–S3 各 1，没有自环，A 的副本不再计数。

## 14. 评审与人工验证清单

- 每条算法规则均可由输入字段、阈值和输出状态复现。
