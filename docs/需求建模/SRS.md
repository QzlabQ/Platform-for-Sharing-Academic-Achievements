## 1. 引言

### 1.1 背景

论文、专利、科研项目和获奖等学术成果分散在不同数据库、机构主页和个人维护页面，存在重复、作者重名、机构别名、更新滞后和成果归属难确认等问题。本系统面向科研从业人员、科研管理人员和普通用户，建立可检索、可追溯、可纠错的多类型学术成果视图。

### 1.2 目标

系统一期形成“采集/导入—清洗治理—统一检索—门户认领—审核纠错—统计分析”的闭环，支持公开数据源和人工导入，保留来源、采集时间、处理状态和审计记录。

### 1.3 术语

| 术语 | 定义 |
|---|---|
| 成果 | 论文、专利、科研项目或获奖记录 |
| 学者门户 | 以科研人员为主体聚合其基础信息和成果的公开页面 |
| 认领 | 科研人员提交身份和证据，申请管理某个学者门户 |
| 消歧 | 判断不同来源中的作者或机构记录是否属于同一实体 |
| 采集任务 | 针对指定数据源和范围执行导入、清洗和入库的任务 |
| P0/P1 | P0 为一期必须能力；P1 为创新或增强能力 |

### 1.4 范围

本轮包含六个核心用例、三个支撑用例、门户认领审核活动图、采集任务状态图、认领申请状态图、SRS、SPEC 和通用材料。汇报 PPT 尚待制作；业务类图、时序图、数据库设计和外部接口设计属于后续阶段。论文全文下载、成果交易、收费数据库抓取、无人审核认领不属于一期。

SRS 描述业务需求；SPEC v1.1 固化内部模块契约、数据清洗、去重消歧、检索排序和验收设计。所有默认阈值属于提议配置，平台实现与性能验收仍待执行。本轮图件采用已确认的本地 PlantUML 方案，尚未制作课程要求的 CodeArts Modeling 源文件。

## 4. 功能需求

### 4.1 数据采集管理（UC-01）

- **目标**：管理员从允许的数据源或人工导入取得成果元数据，并完成任务状态跟踪。
- **参与者**：管理员、公开数据源/外部调度器。
- **前置条件**：管理员已登录并有采集权限；数据源已登记且合规状态允许使用。
- **后置条件**：任务进入成功、失败、重试或已停止；处理记录和审计日志可查询。
- **主成功场景**：管理员选择数据源和范围，创建任务；系统校验配置并置为“待执行”；调度器执行采集、清洗和入库；系统更新进度、计数和更新时间；成功后生成成果记录和来源信息。
- **异常与替代流程**：配置缺失则拒绝创建；源站限频或网络异常则记录失败原因并允许重试；管理员停止任务则进入“已停止”；低置信度消歧记录进入人工复核队列，不直接覆盖正式实体。
- **业务规则**：仅使用公开 API/开放数据或已核验的人工导入；保存 `source_name`、`source_url`、`collected_at`、`license_note`、`review_status`；遵守限频、缓存和退避规则。
- **验收条件**：管理员可创建任务并看到待执行、运行中、成功、失败、重试、已停止六种状态；任务失败原因、重试次数、导入数量和审计记录可查看。
- **补充规则**：首次执行不计重试，最多 3 次重试（共 4 次执行）；停止在页提交边界生效，已持久化记录保留。只有数据、审计和索引同步完成才技术成功，记录人工审核状态独立于任务状态，详见 SPEC MOD-05。

### 4.2 门户认领（UC-02）

- **目标**：科研人员申请管理与本人对应的学者门户。
- **参与者**：科研人员（申请/认领学者）。
- **前置条件**：门户已存在；申请人已登录；申请人未拥有冲突中的有效认领。
- **后置条件**：申请进入“已提交”或“验证中”，申请材料和时间线被保存。
- **主成功场景**：学者搜索并选择门户；填写身份信息和验证材料；系统校验必填字段、文件格式和重复申请；提交申请；系统生成申请编号并通知管理员。
- **异常与替代流程**：材料缺失则提示补充；存在未完成申请则禁止重复提交；门户候选不确定时允许选择候选并标记人工确认；通知发送失败不回滚申请，进入通知重试队列。
- **业务规则**：联系方式默认不公开；认领成功后才允许维护受保护字段；所有申请状态变化保留操作者、时间和原因。
- **验收条件**：申请人能提交合法申请、查看状态和历史；重复申请、缺失材料和通知失败均有明确反馈。
- **状态说明**：填写为草稿；提交条件全部满足才进入已提交。会话失效或材料不全保留草稿；同一门户有未完成申请或已认领时拒绝创建新申请，分别提供进度或申诉入口。通知不阻塞系统验证。

### 4.3 认领审核（UC-03）

- **目标**：管理员核验认领材料并决定通过、驳回或要求补充。
- **参与者**：管理员、科研人员、外部通知渠道。
- **前置条件**：管理员已登录并有审核权限；已提交进入验证中，验证合格进入审核中，当前申请未撤回且版本有效。
- **后置条件**：申请进入已通过或已驳回；要求补充统一记录为已驳回并注明原因；通过时更新门户权限。
- **主成功场景**：管理员打开待审核申请；系统展示申请人、门户、来源和材料；管理员核验身份和成果关联；填写决定及理由；系统更新状态、门户权限和审计日志；通知申请人。
- **异常与替代流程**：材料不足或不可信则写入已驳回和原因；申请人补充材料后，重新校验会话、完整性、申请版本和门户归属，通过后已提交→验证中→审核中。未补充则保持已驳回；无权限或竞态决定拒绝；通知失败不回滚审核结果。已提交/验证中/审核中可撤回。
- **业务规则**：认领必须人工审核；ORCID、机构主页等只能作为辅助证据；驳回必须填写原因；审核前后值和操作者写入审计日志。
- **验收条件**：管理员可通过、驳回或要求补充；申请人可看到决定、原因、时间和通知状态；门户管理权限仅在通过后生效。
- **并发规则**：认领状态、管理授权和日志在同一提交边界内更新；管理员提交携带 expected_version，两名管理员竞争时仅一个成功，另一请求提示刷新，详见 SPEC MOD-06。

### 4.4 检索查看（UC-04）

- **目标**：访客检索和查看公开的学者、机构及多类型成果。
- **参与者**：访客。
- **前置条件**：公开成果已建立索引；查询参数符合格式。
- **后置条件**：返回分页结果、筛选条件、聚合统计、来源和更新时间。
- **主成功场景**：访客输入关键词；选择成果类型、年份、领域和机构过滤；系统解析条件并检索；按可解释规则排序；返回结果；访客查看详情、门户和来源。
- **异常与替代流程**：无结果时返回可调整条件；参数非法时提示修正；检索服务暂不可用时返回友好错误和请求编号；隐藏字段不出现在公开结果。
- **业务规则**：精确标识符命中是独立的第一排序键，其后按相关性、年份、比较标题/名称和对象 ID 排序；仅返回已审核且公开的字段。来源、更新时间和审核状态可查看；多个过滤字段采用 AND，同字段多值采用 OR。
- **验收条件**：支持组合过滤、分页、详情跳转和来源查看；在不少于 10,000 条成果数据上可完成检索和统计演示。
- **分页与隐私**：同一查询在有效索引快照内翻页，默认 20 条、最多 100 条。公开范围收紧后旧快照仍须实时授权检查，隐藏对象不进入结果、总数、分面或关系网络，详见 SPEC MOD-03。

### 4.5 统计分析（UC-05）

- **目标**：为访客和管理员提供可解释的成果聚合分析，并提供一个 P1 创新分析场景。
- **参与者**：访客、管理员。
- **前置条件**：成果具有类型、年份、领域、机构和作者等可聚合字段。
- **后置条件**：返回带口径、时间范围和更新时间的图表或数据摘要。
- **主成功场景**：用户选择统计维度和时间范围；系统校验权限和过滤条件；聚合成果类型、机构、领域和年度趋势；返回结果和数据口径；用户进一步查看明细。
- **异常与替代流程**：数据不足显示样本量；聚合超时返回错误及请求编号，不假装异步任务已建立；P1 无关系数据时不生成误导性结论。
- **业务规则**：基础统计为 P0；合作关系网络或领域热点时序二选一作为 P1 演示；敏感情绪和内部评价不进入公开画像或推荐分数。
- **验收条件**：可按类型、机构、领域和年度生成统计；P1 分析能够展示节点/趋势、数据范围、口径和更新时间。
- **计数口径**：按已审核公开成果 ID 去重；各机构分组允许重复计所属成果，分组和可能大于总数并须注明；主领域为默认领域口径。合作网络只用公开论文和人工确认学者 ID，缺失年份/缺少覆盖数据不得伪造成已观测零值，详见 SPEC MOD-04。

### 4.6 成果管理（UC-06）

- **目标**：认领学者查看并维护本人门户下的成果。
- **参与者**：认领学者。
- **前置条件**：学者已通过认领；目标成果处于可维护范围。
- **后置条件**：成果修改、公开范围或纠错申请被保存并产生审计记录。
- **主成功场景**：学者打开门户；查看论文、专利、项目和获奖；编辑允许字段或调整公开范围；系统校验并保存；更新门户和修改历史。
- **异常与替代流程**：字段格式错误则拒绝保存；成果来源不允许直接修改则引导提交纠错；并发修改冲突则提示刷新；隐藏成果不再出现在访客结果。
- **业务规则**：来源原始字段不可被学者覆盖；敏感联系方式、未公开成果和内部评价默认隐藏；争议修改需管理员审核。
- **验收条件**：通过认领的学者能维护允许字段、控制公开范围、提交纠错并查看处理状态；每次变更可追溯。

### 4.7 支撑用例

**UC-07 登录与身份认证**：验证凭据、建立会话、执行角色授权和会话失效；认证失败不泄露账号是否存在。UC-01/02/03/06 的有效会话作为前置条件，图中不以 include 表示“每次重新登录”；管理员治理操作必须认证。

**UC-08 通知反馈**：对申请、审核、纠错和采集任务状态变化建立站内通知与投递事件；外部渠道异步发送。审核结果通知是 UC-03 的必经行为（include）；失败不回滚决定，记录发送结果并按 SPEC MOD-07 有限重试。

**UC-09 纠错与申诉**：访客可匿名举报公开成果错误，收到回执编号，不获取验证材料或受保护处理细节；认证学者可提交申诉并查看本人详细进度，管理员处理必须认证。提供公开信息错误与成果管理争议两条入口，作为 UC-04/UC-06 的条件扩展（extend），箭头从纠错用例指向基础用例。管理员采纳后产生带审计的修订，驳回须有原因。

## 5. 非功能需求

| 编号 | 需求 |
|---|---|
| NFR-01 可追溯性 | 每条成果显示来源、来源链接、采集/更新时间、处理状态和必要的审核信息。 |
| NFR-02 数据质量 | 自动清洗、去重和消歧只产生候选；低置信度结果进入人工复核队列。 |
| NFR-03 权限隐私 | 按角色授权；联系方式、未公开成果和内部评价默认隐藏；门户支持公开范围控制。 |
| NFR-04 审计 | 认领、纠错、清洗、消歧和人工修改记录操作者、时间、前后值和原因。 |
| NFR-05 合规 | 只使用许可明确或已核验的公开元数据；不抓取收费内容，不绕过登录、验证码或付费限制。 |
| NFR-06 可用性 | 任务和通知失败可重试；错误消息包含可定位的请求或任务编号。 |
| NFR-07 性能与规模 | 支持不少于 10,000 条成果数据的检索、分页和统计演示；查询结果可解释。 |
| NFR-08 一致性 | 模型图、SRS、SPEC 与追踪表使用同一术语和状态名称。 |

## 7. 模型一致性说明

- 用例图中的 UC-01 至 UC-09 与本 SRS 第 4 节一一对应。
- 活动图表现 UC-02/UC-03 的认领审核主流程，并覆盖补充材料、重复申请和通知失败分支。
- 采集任务状态图只使用“待执行、运行中、成功、失败、重试、已停止”；每次失败需保留原因和重试次数。
- 认领申请状态图只使用“草稿、已提交、验证中、审核中、已通过、已驳回、已撤回”，补充材料通过“已驳回→补充材料→已提交”表达。
